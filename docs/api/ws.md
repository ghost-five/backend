# Партия по WebSocket

HTTP описан в [openapi.yaml](openapi.yaml); здесь — то, что происходит за доской.
Состояние партии описано схемой [game-state.schema.json](game-state.schema.json).

## Соединение

```
wss://ghost-five.ru/api/v1/ws?game=SQJXDL
```

- сразу после открытия клиент шлёт `hello` с access-токеном; до этого сервер не
  отвечает ничем, кроме `error`. Токен не кладём в query — он утечёт в логи прокси;
- одно соединение — одна партия. На несколько партий открываются несколько сокетов;
- сервер закрывает сокет кодом `4401`, если токен просрочен: клиент обновляет его
  по `/auth/refresh` и переподключается;
- сокет может оборваться в любой момент. Источник истины — сервер, поэтому после
  переподключения клиент получает полное состояние и перерисовывается.

Все сообщения — JSON-объекты с полем `type`. Неизвестный `type` сервер игнорирует,
клиент — тоже: так протокол можно расширять, не ломая старые версии.

## Клиент → сервер

| type | поля | смысл |
|---|---|---|
| `hello` | `token`, `protocol: 1` | представиться; в ответ придёт `state` |
| `move` | `gameNo`, `round`, `move` | сделать ход |
| `cancel` | `gameNo`, `round` | отозвать свой ход, пока соперник не сходил |
| `resign` | — | сдаться: соперник забирает всю партию |
| `rematch` | `cfg?` | следующий раунд, а после двух побед — новая партия |
| `ping` | — | держать соединение живым, раз в 25 секунд |

`move` — объект из схемы `Move` в openapi.yaml: `kind`, `i`, `take`, `from`, `spent`.

Повтор `move` с теми же `gameNo` и `round` ничего не делает: сервер отвечает текущим
`state`. Это важно при обрыве связи — клиент может переслать ход, не боясь сходить
дважды.

## Сервер → клиент

| type | поля | когда |
|---|---|---|
| `state` | `game` | после `hello`, после каждого изменения, после переподключения |
| `accepted` | `gameNo`, `round` | ваш ход принят и ждёт соперника |
| `opponentReady` | `gameNo`, `round` | соперник сходил; **сам ход не передаётся** |
| `round` | `game`, `events` | оба сходили, ход раскрыт и применён |
| `over` | `game` | раунд закончен: победа, ничья или сдача |
| `clock` | `deadline`, `bank` | часы: до какого времени идёт текущий ход |
| `error` | `code`, `message` | что-то пошло не так, партия продолжается |
| `pong` | — | ответ на `ping` |

`game` — объект `GameView` из openapi.yaml: правила, игроки, счёт партии, состояние.

## Тайна хода держится сервером

Это главное отличие от нынешней версии. Сейчас оба игрока видят базу, поэтому ход
прячется хешем (commit-reveal с солью). Серверу прятать нечего: он просто **не
рассылает чужой несделанный ход**. Соперник получает только `opponentReady`.

Отсюда следует:

- соли и хешей в протоколе нет;
- `cancel` работает ровно до того, как сходил соперник, — сервер это знает точно;
- подделать чужой ход нельзя: клиент вообще не участвует в применении правил.

## Часы считает сервер

`deadline` — момент, когда текущий ход истечёт. Клиент рисует обратный отсчёт от
своих часов, но решение «не успел» принимает сервер: он применяет пропуск сам и
рассылает `round`. Расхождение часов клиента и сервера на секунду ничего не меняет.

Когда основное время кончилось, из запаса (`bank`) списывается перерасход. Это
делает сервер при применении хода; клиент показывает `bank` из `state`.

## Порядок одного хода

```
клиент A  --move-->  сервер
          <-accepted--
                       сервер --opponentReady--> клиент B
клиент B  --move-->  сервер
          <-round (обоим: состояние + события)-
```

Если один из игроков не успел, сервер сам подставляет `pass` по истечении
`deadline` и рассылает `round`.

## Ошибки

`error.code` из закрытого набора openapi.yaml. В партии встречаются:

| code | что случилось |
|---|---|
| `stale_move` | ход относится к прошлому раунду — клиент отстал, перечитайте `state` |
| `move_not_allowed` | правила такого хода не допускают (нет выстрелов, магнит остывает и т. п.) |
| `game_over` | партия уже закончена |
| `forbidden` | вы не игрок этой партии |

Ошибка не закрывает сокет: после неё можно ходить дальше.
