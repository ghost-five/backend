# Контракт API

Единственный источник правды о том, как общаются фронт и бэк. Реализации меняются,
контракт остаётся — по нему пишется и сервер на Go, и клиент на React.

| Файл | Что внутри |
|---|---|
| [openapi.yaml](openapi.yaml) | HTTP: аккаунты, друзья, лобби, история, рейтинг |
| [ws.md](ws.md) | WebSocket: сама партия, ходы и часы |
| [game-state.schema.json](game-state.schema.json) | Состояние партии — то, что считает движок |

## Как этим пользоваться

**Go.** Структуры из состояния партии генерируются из JSON Schema, клиенты и
серверные интерфейсы HTTP — из OpenAPI:

```
go run github.com/atombender/go-jsonschema@latest \
  -p game docs/api/game-state.schema.json > internal/game/state.go
go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest \
  -generate types,chi-server -package api docs/api/openapi.yaml > internal/api/api.gen.go
```

**TypeScript.** Для фронта типы берутся теми же генераторами (`openapi-typescript`,
`json-schema-to-typescript`). Руками типы не пишем: разъедутся.

## Правила изменения

1. Меняется контракт — меняется этот каталог, и только потом код.
2. Несовместимые изменения — через новую версию пути (`/api/v2`), а не правкой
   старой. Пока в бою один клиент, это дёшево; когда появятся мобильные — спасёт.
3. Поля только добавляются. Удаление и переименование — несовместимое изменение.
4. Правила партии живут в движке, а не в API: если поведение спорно, смотрите
   золотые тесты `fixtures/` в репозитории `frontend` — там оно записано исполняемо.

## Проверка

Пока движок один и лежит в `frontend`, обе проверки запускаются там:

```
node tools/schema-check.mjs     # состояния из фикстур сходятся со схемой
node tools/fixtures-check.mjs   # движок считает партию как записано
```

Когда правила появятся здесь (на Go), `schema-check` переезжает сюда: схема
состояния и реализация обязаны сходиться в том репозитории, где реализация.
